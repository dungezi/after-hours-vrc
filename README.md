# 夜航 · AFTER HOURS

一个可以在线游玩或本地部署的 **VRChat 主题文字策略与关系模拟器**。世界探索、砂糖文化、原创角色故事、改模与创作，组成一段 28 夜的旅程。无需 VR 设备，也不连接真实 VRChat 账号。

**[直接在线游玩](https://dungezi.github.io/after-hours-vrc/)** · [下载项目](https://github.com/dungezi/after-hours-vrc/archive/refs/heads/main.zip)

网页版与本地版使用相同的游戏内容。网页存档保存在当前浏览器；与本地版、其他浏览器的进度分开，可以通过游戏里的存档导出／导入迁移。

## 启动

先安装 [Node.js](https://nodejs.org/) 22 或更高版本，下载并解压项目。项目没有第三方运行依赖，无需 `npm install`。

### Windows 一键启动

1. 双击 `启动夜航.cmd`。
2. 启动器等待服务就绪后，自动打开专用 Edge 窗口（没有 Edge 时使用 Chrome）。不用手动输入地址。
3. **关闭所有夜航专用窗口后，服务会在约 5 秒内自动停止。** 刷新页面、最小化或长时间不操作不会误停服务。
4. `停止夜航.cmd` 可以手动停止服务。重复启动会复用已有服务，并打开新的夜航窗口。

专用窗口使用本项目中的独立浏览器配置，游戏存档会保留。它与 Codex 内置浏览器及日常浏览器的存档分开；已有进度可在原浏览器导出，再到新窗口导入。浏览器首次打开失败时，服务最多等待约 90 秒后自动停止。

也可以在本目录运行 `npm start`，效果与双击启动相同。如端口被其他程序占用，在 PowerShell 中设置 `$env:PORT=4174`，再运行 `npm start`，启动器会打开新端口。

### macOS、Linux 或手动启动

在项目目录运行：

```sh
npm run serve
```

然后在浏览器打开 `http://127.0.0.1:4173/`。也可直接运行 `node server.mjs`。这种模式用终端的 Ctrl+C 停止服务；专用窗口的自动停止仅用于 Windows 启动器。

所有图片都是游戏自带的原创 SVG，字体使用系统字体，启动后可以断网游玩。需要通过本地服务打开，直接双击 HTML 不会加载模块。

## 发布自己的网页版

Fork 本仓库，在仓库 **Settings → Pages → Build and deployment** 中将 Source 设为 **GitHub Actions**。运行 **Actions → Test and publish game → Run workflow**；之后推送 `main` 会先运行测试和发布文件检查，通过后将 `dist/` 部署到 GitHub Pages。Fork 后请把本文顶部的网址换成自己的 Pages 地址。

也可把 `dist/` 的内容上传到其他静态网站托管服务，不需要服务器数据库或环境密钥。脚本和样式使用相对路径，支持部署在仓库子路径下。

## 数据与公开文件

游戏不设账号、广告、埋点或远程存档，角色与对白均为原创虚构。玩家输入的昵称、选择、关系、相册与日记仅保存在浏览器本地；导出的文件由玩家自行保管。游戏源码不包含任何玩家的实际存档。

公开源码排除独立浏览器配置、本地存档、验证截图、日志、临时发布资料和凭据。GitHub Pages 仅发布 `dist/`。在线网页的正常访问仍由 GitHub Pages 提供服务；点击文化来源链接会打开对应外部网站。

维护检查：`npm test` 验证游戏与服务行为，`npm run check:publish` 检查已跟踪文件中常见的凭据、个人目录、邮箱、手机号及本地资料。自动扫描用于辅助检查，发布前仍应查看提交文件清单。

## 玩法

这一版以阅读与选择为主：28 个夜晚，每晚 3 次行动。探索、聊天、约会、创作和拍照都能进入故事；告白、边界讨论、告别则有专门的对话。选择剧情选项不额外消耗行动。故事不再限制每晚只能读一段。

- 六位角色会随夜晚移动到不同世界，在线时间仍各不相同。世界详情显示当晚在场的人物，人物页显示当前地点；偏好影响约会体验，不限制人物出现地点。
- 保留 27 段世界事件及个人故事，另有 12 段角色相处对话、10 段群像故事。群像选择会同时影响两人与你的关系、角色彼此的熟悉度，以及后续故事的呼应；当两人已经是砂糖时，还会改变他们之间的信任与压力。
- 当前世界显示「继续探索」，其他世界显示「跃迁」。跃迁将移动与探索合成一次行动。查看详情或切换页面不消耗行动。探索侧重偶遇与世界片段，聊天侧重指定朋友的经历。
- 砂糖发展先经过个人故事和两段角色专属的心意前相处：共同邀请、表达脆弱、错过之后重新理解对方。两段至少间隔两夜；读完后，告白需要亲密 30、信任 30、相处 4 次。进入专属对话后，对方可以立即回应、继续了解或明确拒绝；你也可以暂缓或拒绝建立关系。不会只点击按钮就自动成为砂糖。
- 等待回应的进度取决于角色性格、后续相处、信任、边界沟通，以及浮动的考虑时间，不固定为三晚。阿澈选择朋友关系。回应有单独的中央结果窗口，保留到玩家确认；刷新或导入存档也能恢复未确认的回应。
- 可以拥有多段砂糖关系。坦诚会进入各方协商；隐瞒会引出之后被发现的剧情。后续还有时间分配、合照公开范围等故事。零点、凛、弥生愿意讨论知情的开放关系，雨音和小满可以选择退回朋友关系，各自的决定都会实际生效。
- 连续 3 晚未相处会使砂糖关系逐渐疏远，压力达到 75，或长期缺少相处且信任较低时，会开始 NPC 主动提出的关系变化故事。先读两段跨夜前置，再进入分开提议；不会达到数值就立即解除关系。重复约会仍会增加压力。
- 在人物详情选择「邀请朋友一起相处」，可邀请另一位已认识且当晚在线的朋友。支持共同兴趣、留下独处空间、偏袒或起哄，都会影响两人与你的关系和他们彼此的熟悉度；已有 NPC 砂糖的信任与压力也会改变。相处能为指定角色组合开启后续心意故事，关系仍由 NPC 自己确认。
- 9 种结局、14 个成就；完成旅程得到碎片，永久解锁回忆，每局最多携带 3 份。

## 拍照与相册

点击「留一张照片」后，先选择独自拍当前世界的风景，或与已认识、今晚在线且同在当前世界的朋友一起拍；选择界面本身不消耗行动。人物页也有「在当前世界一起拍照」，不在同一世界时会说明需要先跃迁。每夜仍最多拍一次，消耗 1 次行动、8 精力与 4 现实平衡，拍照剧情中的选择不额外消耗行动。

新增 **60 段拍照专属故事**：6 个世界 × 6 位好友的 36 段取景故事、每个世界两段独自拍景，以及每位好友两段跨夜后续。拍摄前先讨论构图与是否入镜；可以合照，也可以选择只拍风景。不同世界的灯光、场景细节与朋友性格会实际进入对话。

好友后续需要此前实际读过一次拍照故事、个人故事进度、信任与共同相处，并至少间隔两夜；会提到先前照片的夜晚、地点，以及当时是否选择不出镜。第二段后续还需要读完第一段并再隔两夜：阿澈需要完成朋友的个人故事，其他角色需要已经确认砂糖关系。拍照不会跳过告白、自动确认关系或替对方同意亲密姿势。

每段拍照故事每局只读一次。没有新的合适分支时，仍显示与当前地图、同行者和旧照片相关的拍摄结果，并留下新照片，不重复发放故事的关系奖励。相册保存照片标题、所在世界、夜晚、同行者、实际入镜者与选择结果；所有照片仅保存在本机，不自动上传或公开。旧版照片保留原有地点、夜晚与同行者，不会凭空补出曾经读过的拍照剧情。

## 数值与生活安排

共有 72 段原创日常：6 个世界各 6 章，6 位角色各 6 章，每章都有不同的选择与后果。本次各续写第五、六章，新增 24 段，涉及世界社群的变化、创作上线后的维护、邀请与作息、相册与承诺等。后章需读完前章，并间隔至少两夜；角色日常还需实际相处。每段日常每局只出现一次。原有聊天与约会共用已读记录，两段对话按顺序跨夜展开；没有新分支时仍显示行动结果并记录实际变化，不会强行重放旧对白。群像会检查它引用的共同经历，作品反馈、合照误会等事件也需先发生对应行动。

NPC 会按性格主动推进与你的关系：凛、小满偏向直接表达；零点先确认共同时间与彼此期待；雨音、弥生先试探，得到回应后再认真说清心意。主动剧情需要个人故事、两段心意前的相处、足够信任和亲密、边界沟通，以及当晚在线。雨音从第 22 夜、弥生从第 23 夜起，可能因旅程临近结束更愿意直接开口，所需亲密和等待间隔略降低，但不会跳过前置故事。现实时间经过不代替新的共同相处。

你可以回应期待、接受明确的邀请、表示需要时间，或保持朋友。试探不会自动成立砂糖；正式关系需要你明确确认，并显示持续到点击确认的结果。拒绝不扣信任，也不会重复追问；等待最多出现一次内容不同的后续邀请，仍未确定可以之后主动表达心意。阿澈仍选择朋友关系。已有排他约定会阻止新的主动邀请；开放关系则须先有相关角色的知情共识，剧情会明确提到已有关系。朋友之间的心意确认若连续暂缓，也不会无限循环同一段。

制作、社交高于 40 后增长逐步放缓；心情高于 70 后正向收益减小，每夜自然回落 4 点。数值上限仍为 100，结果与日记显示实际发生的增减，不显示被上限截掉的收益。

| 行动 | 精力消耗 | 现实平衡 |
| --- | --- | --- |
| 探索／跃迁 | 13～18，天赋和回忆可减免 | −5 |
| 聊天 | 10 | −4 |
| 约会 | 16 | −7 |
| 边界沟通 | 8 | −2 |
| 邀请两位朋友一起相处 | 15 | −6 |
| 告白 | 10 | −4 |
| 拍照 | 8 | −4 |
| 制作 | 18，另需 10 资金 | −6 |
| 工作 | 10，获得 50 资金 | +13 |
| 休息 | 恢复 28 | +16 |

剧情选择另有各自的增减。新开局基础精力为 65。用满三次行动的夜晚恢复 18 精力，用两次恢复 24，用零或一次恢复 30；舒适头带和恢复回忆各额外 +3。连续高消耗行动需要安排休息；不会仅靠结束夜晚就一直回满。提前结束这一夜恢复 3 现实平衡；三次行动全用完则没有这项恢复。「现实锚点」每夜额外 +2 平衡。

进入新夜晚时，屏幕中央提示当前夜数，持续 3 秒。普通操作提示持续 4.5 秒。精力不足可以休息，现实平衡不足可以工作或休息；线上活动与生活安排都影响结局。

## 各页面的作用

| 页面 | 主要用途 |
| --- | --- |
| 世界探索 | 选择世界跃迁，偶遇在线朋友，进入世界故事。顶部显示故事进度与等待中的心意；世界详情显示实际收益和今晚在场的人物。 |
| 朋友与砂糖 | 查看当前地点、偏好、个人故事、NPC 关系网络；聊天、约会、邀请两人共同相处、边界对话、告白与告别。约会发生在当前世界。 |
| 创作工坊 | 推进 Avatar、世界、聚会项目，购买摄影、舒适与全身追踪设备。 |
| 回忆档案 | 用碎片解锁永久回忆，选择下一局携带的 3 份加成；查看日记、相册、成就与结局。 |
| 玩法与存档 | 查看规则、导出或导入存档、导出文字日记、重新开局和阅读文化来源。手机尺寸下，右上角书本图标打开玩法说明，齿轮图标打开存档管理。 |

侧栏显示精力、心情、制作、社交与现实平衡，顶部显示资金。右侧显示当前夜晚和剩余行动，并提供拍照、休息与工作快捷操作。手机布局会把状态压缩到页面上方，把快捷行动放在主要内容下方。

第一轮建议先探索和认识朋友，再根据偏好决定关系或创作路线；精力不足就休息，资金不足就工作。避免只顾增加亲密而忽视信任、压力和现实平衡。

## 存档

自动存档位于当前浏览器的本地站点数据中。通过「玩法与存档」导出 JSON 备份、导入存档，或导出本轮文字日记。导入需要确认，且会检查格式和数据范围。

「下载旅程备份／导出完整存档」得到 JSON 文件，包含当前进度、关系、日记、相册、已经作出的剧情选择、待续剧情、等待中的告白和永久回忆。可用于备份、迁移或回到导出时的分支；重新导入会替换当前进度，并不会自动合并两份存档。自动保存只记录当前旅程，因此重开前下载文件可以留住旧旅程。

旧版存档会自动升级，并在同一浏览器中保留升级前的原始副本。已经成立或正在协商的旧砂糖关系保留；尚未确认的关系会补读新的前置故事，抢先排队的告白会等待前置完成。当前精力不被重置，后续行动与夜间恢复按新规则计算。旧版制作、社交超过 40 的部分按一半换算（例如 100 → 70），剧情、关系、日记和永久回忆保持；新开局使用完整的新规则。也可以直接导入旧版导出的 JSON 文件。

浏览器、端口或设备变化时需要通过文件迁移存档。新开局替换本轮关系、日记与相册，已经结算的永久回忆、成就与碎片保留。未完成的旅程不会获得结算奖励。

旅程结束后，结局窗口与各页面的结束提示都有「开启下一局」按钮，可直接选择下一轮天赋和设备。也可以先整理跨局回忆或下载旅程备份。

每次新开局会依次呈现雨音、阿澈的初次相遇，且不消耗行动。探索时认识新朋友也会先显示相遇剧情；同次行动触发的其他故事保留在队列中，确认当前结果后再继续，不会相互覆盖。待续故事随存档保存。

「已经遇见」与「读完初次相遇」分别记录。群像和关系交织剧情会等待相关角色的初次相遇全部读完；旧存档中抢先出现的群像会延后并保留，尚未读完的相遇优先恢复。第二版存档自动升级时，原有属性和进度保持，也会在当前浏览器保留升级前的副本。

朋友之间也有自己的砂糖故事：小满与凛、零点与弥生、雨音与小满、零点与凛、凛与弥生会从对应群像或共同相处开始，再经过两段专属前置故事：逐渐靠近，以及错过、磨合之后重新理解。前置故事之间、第二段故事与心意确认之间，分别至少间隔两夜；熟悉度不足还需继续相处。主角可亲自经历，或由已经认识且在线的另一位 NPC 转述得到当事人同意分享的近况。转述与亲历共用故事进度，不会重复刷取。随后才会进入心意确认和相处安排。零点、凛、弥生可以拥有多位砂糖，已有砂糖会参与新关系的边界协商，之后还会出现几份邀约共用一个夜晚的剧情。雨音、小满的排他期待仍会影响新关系；涉及玩家的开放关系需要另行沟通并取得玩家同意。

你的建议会影响 NPC 与你的信任，也会改变 NPC 之间已有关系的信任与压力；隐瞒、偏袒或要求所有人持续陪伴，可能引出告别。关系状态显示在「朋友与砂糖」中的「朋友们的关系故事」，与玩家自己的关系分别保存。NPC 可以因相处压力或生活期待变化向另一位 NPC 提出告别，关系不会因为旁人劝说而强制保留。

玩家的砂糖搭档也能主动开始关系谈话：高压力或长期缺少相处且信任较低时，先显示关系变化的前置故事。你与 NPC 都可以表达还不愿分开，之后可能共同选择调整，也可能认真讨论后仍然告别；继续、待讨论和结束都有显著提示。告别和共同经历继续留在日记及存档中。

## 关系变化、分开与后续

玩家关系与 5 条 NPC 砂糖关系线都有独立进度：先讲具体的变化，再谈各自还能承担的愿望，两段前置至少相隔一夜；之后再隔一夜，才进入正式分开提议。人物页的「谈谈关系是否继续」启动同一流程，消耗 1 次行动、8 精力；后续剧情选择不额外消耗行动。压力、疏远或现实安排变化可以促使 NPC 开始谈话，NPC 之间的提议也可能来自任一方。

另一方可能不愿分开。NPC 是否挽留、提出者是否愿意调整，会参考性格、信任、压力及实际分歧；玩家的支持或催促也会影响 NPC 之间的讨论。挽留之后至少再隔一夜认真回应：双方愿意时保留砂糖，仍决定离开时则确认分开。不愿分开会被写进剧情，但不能单方面替另一人答应继续。重新讨论有次数限制，已读前置不会为了重提而重复播放。

分开后还有两段专属后续，各至少相隔两夜：先处理照片、共同作品、联系范围与隐私，再谈重新问候或各自继续生活。可以共同确认按朋友身份联系，也可以继续留出距离或暂不联系；后一种选择不会强制安排重逢、自动复合或删除旧照片。暂不联系的玩家关系会限制聊天、约会、邀请与合照，独自拍风景仍可进行。NPC 之间的故事可以亲自听见，也可以由已认识的朋友转述双方同意分享的近况，或通过共同留下的消息推进。

旧版尚未确认的即时告别会转入新的前置，不会补造已读经历；已经分开的关系保留结果，并可以读新的后续。第 28 夜仍未完成的提议不会为了结局跳过跨夜顺序或强行解除关系，结局会注明还有需要说完的话。
